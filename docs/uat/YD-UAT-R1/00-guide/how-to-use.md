# 如何操作、填写与保存

1. 在自己的**私有副本**中保留完整目录结构，不在公开仓库填写患者、账号、口令、Session 或未经授权的财务和临床信息。先读[环境清单](environment-and-data.md)，环境未准备好时停在 NOT_RUN；必要时用 BLOCKED 并写阻断原因。
2. 从[总入口](../README.md)按岗位、场景或功能进入具体用例，核对实际版本、门店、账号权限、合成对象、阶段及前置。每个场景的步骤链接到同一功能用例，不要再执行已经提交过的动作。
3. 按用例的操作/预期逐行进行；观察具体状态、数值、责任人或可见内容。结果未知、数据不一致、权限异常、来源无法唯一识别时停止受影响动作，记录最后事实并找环境负责人核实，不盲目再次提交。
4. 在该用例的用户填写区记录日期、环境版本、岗位门店、浏览器/宽度/缩放、实际观察、结果、失败步骤、可重复条件和问题等级。UI 满意度另填；环境阻断、缺证据、缺陷和偏好分开记录。
5. 在桌面、平板和窄屏三档分别记录实际浏览器、窗口宽度和缩放；按用例适用情况观察文字、控件、横向滚动和键盘焦点，不猜测通过。若设备条件不具备，记录未测原因，不把它当产品缺陷或通过。
6. 截图保存在该用例的 `../images/用例ID/`。例如结算用例中的 `![步骤3：未付清账单](../images/UAT-FIN-002/03-unpaid.png)`。命名用“步骤编号-用途-可选序号.png”；保留原图和此前失败图，标注图单独保存。图片内容避免秘密和真实受保护信息。
7. 在[问题汇总](../40-results/issues.md)分配问题 ID 并引用原用例和截图相对路径；在[阶段登记](../40-results/stage-status.md)、[UI意见](../40-results/ui-feedback.md)、[复验登记](../40-results/retest-register.md)引用原记录，不重写一套结果。需要新需求时记在[需求反馈](../40-results/requirements-feedback.md)。
8. 验收完成后在[最终用户结论](../40-results/final-review.md)记录范围、未测项及意见，把整个私有副本交给用户指定的 GPT/Codex；保持相对路径。若以后需要同步公共仓库，先检查真实患者、账号、秘密、Session及未经授权财务/临床内容。

任何持久提交（例如权限变更、到店、治疗、发药、收费、退款、日结、原件生成）结果不明时先停止并核实；不要为了截图重新做一遍。环境负责人负责合成测试策略和账号，用户不需要数据库操作。
