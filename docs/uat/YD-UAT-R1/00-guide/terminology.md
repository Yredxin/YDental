# 术语与结果

| 术语 | 定义 |
|---|---|
| UAT | 用户验收测试 |
| Case / 用例 | 独立可执行且有结果记录的验收单元 |
| Scenario / 场景 | 由一个或多个角色及用例组成的业务流程 |
| Role / 岗位 | 用于体验的业务身份；名称本身不授予权限 |
| Capability / 权限类别 | 系统真实授权维度；不同于工位业务能力字典 |
| Precondition / 前置条件 | 开始操作前必须成立的事实 |
| Action / 操作步骤 | 用户实际执行的动作 |
| Expected Result / 预期结果 | 可明确观察和比较的结果 |
| Actual Result / 实际结果 | 用户亲眼看到的事实 |
| Reproduction Steps / 复现步骤 | 可以重复定位同一问题的条件和动作 |
| UI/UX | 视觉及交互体验 |
| Evidence / 证据 | 截图、实际记录及对应版本 |
| Retest / 复验 | 问题修复后重新执行有明确范围的用例 |
| Blocker / 阻断项 | 使当前验收无法安全继续的问题 |

## 验收结果

- `NOT_RUN`：未执行；所有用例初始值。
- `PASS`：本人执行了适用步骤，观察与明确预期一致。
- `PARTIAL`：只完成部分或证据不完整；列出具体未完成范围。
- `FAIL`：已执行步骤出现与预期不符；记录步骤和事实。
- `BLOCKED`：前置或安全条件不足，不能继续；记录原因。
- `N/A`：经判断不适用；写明理由，不代替未执行。

## 验收层级

- L1：只读及操作体验。
- L2：单岗位合成业务操作。
- L3：跨岗位业务闭环。
- L4：专项技术证据，由Codex准备、用户审阅。

## 问题等级

- P0：数据、资金、临床安全或严重权限问题，停止受影响操作。
- P1：核心业务流程失败。
- P2：普通功能缺陷。
- P3：非阻断体验建议。

UI满意度单独填写：**满意 / 基本可用但需优化 / 需要重新设计 / 不适用**。UI偏好、产品缺陷、环境限制和证据不足分别记录，不混为同一种结果。
