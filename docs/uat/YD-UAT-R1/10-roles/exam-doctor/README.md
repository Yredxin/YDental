# 检查医生

当前环境 **ENVIRONMENT_NOT_READY**；所有用户用例初始 **NOT_RUN**。本岗位是业务体验身份，不是固定权限模板或自动授权。先由负责人核对实际账号、当前门店、允许公司范围、类别等级及业务前置；只用独立合成数据。

## 职责与门诊作用

接收已报到的检查任务，执行检查并确认独立结果，向原医疗接诊提供结果。

## 真实权限及范围

当前门店 exam write、匹配的检查能力及有效资质、合法工位连接；外部检查由前台先对派生任务报到。结果和患者返回为不同状态。

16 个实际授权类别及等级说明参见 [岗位与权限矩阵](../../00-guide/role-permission-matrix.md)。业务能力、Odoo 组、门店成员关系与权限类别是不同条件，不能从岗位名互相推导。

## 推荐顺序与功能用例

按照列出的用例及其前置依赖顺序进行；跨岗位项只执行本账号承担的部分，其余交由有权人员完成。操作与原始结果只保存在对应的用例内。

治疗医生及前台先完成 [UAT-EXM-002](../../30-functions/clinical-exam/cases/UAT-EXM-002.md) 前半的医嘱、保留和报到 → 检查岗位执行 [UAT-QUE-001](../../30-functions/intake-queue/cases/UAT-QUE-001.md) → [UAT-EXM-001](../../30-functions/clinical-exam/cases/UAT-EXM-001.md) → 原医生执行 UAT-EXM-002 后半的返回恢复。

[UAT-QUE-002](../../30-functions/intake-queue/cases/UAT-QUE-002.md) 是单独的异常用例，须另备已叫号但尚未开始执行的合成任务，不复用上述已执行的检查任务。

每项先核各用例的页面、权限、数据和停止条件。观察桌面、平板、窄屏三档布局及实际浏览器、宽度、缩放，在原用例记录实际 UI 意见；不将不同岗位或设备的体验代填为 PASS。

## 常见异常与限制

本组用例覆盖外部检查，同工位检查仍是缺口；不要把检查结束推断为治疗完成。

任何持久提交结果不明、对象或权限不符、来源不能唯一识别时停止受影响动作，由环境负责人核对，切勿盲目重试。真实患者、资金、正式签署、外部通知与生产环境不在本资料制作授权内。
