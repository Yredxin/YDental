# UAT-ACC-001｜门店和员工准备

- 所属阶段：U00 环境与组织准备；层级 L2。
- 参与岗位：具备相应授权的集团管理者或店长／人员授权者；岗位仅是体验视角。
- 真实权限：创建门店要求集团管理员且目标公司在其允许公司范围；创建／关联员工要求当前门店有效成员且为店长或 `personnel=write`，或者在允许公司范围内的集团管理员。普通 personnel 写不能超出自身授权层级或更改自己。涉及跨公司扩权时需集团管理员。可见菜单还需 YDental 内部用户组。
- 需求与技术阶段：R02、R03、R05；S01-T01/02/03/04/05/06/08/09/10、S03-T12/13。对应计划项，非用户验收通过。
- 业务作用：把合成员工关联到正确门店，为后续角色体验提供独立账号。
- 核心行为：确认当前门店和员工列表；只对新建、明确授权的合成对象创建或关联一次。
- 页面：登录后从 YDental 菜单进入 **Store and staff**（门店与员工，`/ydental/access`）；可见 Current store、Store、Switch store，具备管理条件时可见 Staff、Add staff、Link existing account to this store。界面显示语言以环境为准。
- 前置：未来验收环境已确认固定候选并与历史数据库隔离；已有有权管理者、活动测试门店及已私下准备的合成姓名与唯一测试登录名。若测试创建门店，另准备已授权公司 ID、有效 IANA 时区和集团管理员；页面已有当前作用域。员工的后续业务权限不因创建账号自动授予。禁止使用真实人员或历史账号。
- 当前可验收准备状态：**ENVIRONMENT_NOT_READY**；以下为源码支持的候选流程，尚未在用户环境验证。

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 用准备好的管理账号打开 Store and staff，查看 Current store。 | 页面显示当前门店名称，或未选择时为 `-`；不要把 `-` 当作已选门店。 |
| 2 | 在 Store 选择已授权的测试门店，点 Switch store。 | 返回页面后 Current store 显示所选门店；不属于账号的门店不应出现在可选列表。 |
| 3 | 由环境负责人事前通过获准入口确认合成登录名全局未占用，并在 Staff 核对可见姓名和 ID；记录测试门店和私有编号。 | Staff 只列 Account ID、Name、Employee ID 和 Store manager，不显示 Login；登录名是否被占用不能由此表证明。发现碰撞或无法确认时停止。 |
| 4 | 在 Add staff 输入合成 Name 和 Login，点 Create or link internal account 一次。 | 返回门店员工页面；该登录名若对应活动内部账号会关联，否则创建内部账号并关联当前门店。不要假设已发密码。 |
| 5 | 查看 Staff，找到该合成姓名并记下显示的 Account ID 和 Employee ID。 | 新关联员工出现在当前门店列表；身份与准备清单相符。 |
| 6 | 若另有明确准备的活动内部账号，填写其 Account ID 并点 Add store membership 一次；否则跳过。 | 目标与当前门店关联；跨公司权限不足时被拒绝，不得以其他身份绕过。 |
| 7 | 在授权的合成场景下，如需测试集团建店，填写 Name、允许范围内 Company ID 和有效 IANA timezone，点 Create operating store 一次。 | 请求返回员工页面；该页面不提供新店列表的直接读回，负责人须在获准的门店管理入口独立确认新店名称、公司及时区；若无可见读回入口，记为待验，不能据跳转认定建店成功。新店不自动成为当前账号的可选成员门店，须按授权配置关联后才能切换。 |

异常与权限负例：无管理权限者不应看到人员管理表单；无有效成员或不在允许公司范围的操作应被拒绝。已有停用或非内部同登录名不可直接关联。此例不测试正式策略、邀请邮件或真实账号停用。

一次性提交：第4、6、7步改变账号、门店成员或门店；先核对对象，响应不明立即停止并由负责人核实，不重按、不重复创建。历史门店、员工及责任一律不改。

结束条件：准备的合成员工与门店关联已由页面核实，或记录拒绝与阻断原因；人员权限配置衔接 [UAT-ACC-002](UAT-ACC-002.md)。
