# UAT-LAB-004｜独立合成工单的戴用完成及成本来源查看

- 所属阶段：U06；参与岗位：治疗医生、仓库负责人、采购权限人员；层级 L3。
- 真实权限：当前店 medical write 与 warehouse write、工单模型权限及公司范围；采购来源与金额字段另需 Odoo `purchase.group_purchase_user`。患者治疗与库存权限需独立满足。
- 需求／技术阶段及 TC：R23；S11-T13–18。
- 当前可验收准备状态：DATA_NOT_READY；SOURCE，不代表实际环境或用户验收。

## 业务作用与核心行为

区分模拟加工已入库和实际戴用完成，记录真实库存出库；由有权采购人员核对发出时冻结的合成采购成本来源，不把供应商成本当患者费用。

## 页面与前置条件

进入 Dental Laboratory → Work orders。负责人须提供按 UAT-LAB-002 创建、发出并入库的另一独立合成工单（available，未返工、未戴用），同公司同供应商已确认且唯一的原生合成采购服务行；医生须在工单入库后，另按 UAT-TRT-002 在不同于制作来源的独立接诊执行段，合法产生同店同患者的 confirmed 实际戴用治疗事件。负责人须以事件标识、执行段及时间核实其发生在工单入库之后；无法证明任一条件则 BLOCKED。记录两个原 RUN；不得把旧已提交对象或 UAT-LAB-003 的返工对象作为本例来源。无法唯一识别事件、成本或库存批次则 BLOCKED。

## 有序操作和预期结果

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 采购权限人员打开目标合成工单，核对工单、供应商、患者和状态。 | 目标工单 available、与对应原 RUN 一致。 |
| 2 | 在工单事件列表查看发出事件的采购行、供应商成本、币种及采购状态／快照。 | 所示来源与负责人提供的唯一已确认采购行一致；金额为供应商成本，不称患者账单或已付款。无法查看时标 BLOCKED。 |
| 3 | 由有权人员在工单中选择负责人核定的同患者同店 confirmed 戴用治疗事件，保存。 | 该字段保存是持久写；所选事件标识、confirmed 状态、患者、门店及入库后的不同执行段与负责人核定一致。结果不明先停并核读回，不盲目重试。 |
| 4 | 核对拟使用的合成批次和数量，点击 Record actual fit 一次。 | 工单状态变为 done，显示戴用治疗事件与库存事件；不等于支付、退款或外部交付。 |
| 5 | 只读查看原工单关联及库存事件。 | 戴用事件和库存事件各能唯一定位，数量对应工单；无法确认则停止，记录实际观察。 |

## 异常与权限负例

错误患者、门店、非 confirmed 来源、无仓库写权限或不足库存时不得完成。负例需要另一个安全合成工单，不得反复提交本例。

## 一次性提交及停止条件

第3步保存事件关联是持久写，结果不明先核字段读回，不能盲目重试；第4步产生库存出库并完成工单；治疗事件由 UAT-TRT-002 单独执行，不能为本例重复产生。响应未知先核工单状态、事件和库存，不重试或补写。历史业务保持不变。

## 结束条件及后续衔接

唯一 done 工单、治疗及库存事件可读后结束；戴用后返修另需合成来源和审批，不在本例自动执行。
