# UAT-FUP-003｜医生发起有时段跨店转诊

- 所属阶段：U06；参与岗位：源门店治疗医生、目标门店前台；层级 L3。
- 真实权限：源店 medical write、有效接诊及文书编辑租约；目标前台 frontdesk write、目标公司范围及患者门店关系。目标供给与时段须通过原生资格校验。
- 需求与技术阶段：R23；S11-T07–12。
- 当前可验收准备状态：DATA_NOT_READY；有时段合成目标供给、未来合成患者到店模拟和两个门店账号须由负责人准备。源码是 SOURCE，不代表实际环境验证。

## 业务作用与核心行为

在源店锁定目标门店的预约资格，观察创建的目标任务；此动作不等于目标患者实际到店、报到或源接诊结束。

## 页面与前置条件

医生从临床导航进入 `/ydental/treatment` 的 Cross-store referral；目标前台进入目标店 `/ydental/intake` 的 Service intake。负责人须准备独立合成患者、源店正在进行的合法医疗接诊、已保存文书及编辑租约、另一店有效目标服务映射和唯一可售已发布时段；须有可用容量和合法 isolated_test 测试政策，demo 不可售，不能自行改数据库身份或启用正式政策。负责人须提供 UTC 起止，能明确识别目标患者、门店和服务，并事先确认该合成患者当天在目标店没有已有到店记录；条件不明 BLOCKED。不得使用已发起转诊的历史源。

## 有序操作和预期结果

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 源医生打开治疗工作台，核对当前合成患者及门店。 | 患者、当前接诊与准备记录一致；租约有效。 |
| 2 | 在 Cross-store referral 选择负责人指定的另一门店服务，选择 Timed reservation。 | 所选目标店不同于源店，目标服务和时段对应准备记录。 |
| 3 | 按负责人提供的 UTC 填 Slot start 和 Slot end，填写合成原因，valid until 留空。 | 起止与目标供给一致，未来截止字段为空。 |
| 4 | 点击 Initiate referral only 一次，在页面确认框核对后确认一次。 | 出现 Timed target qualification task 与编号；记录本次 RUN 和编号。 |
| 5 | 目标前台切换目标门店，打开 Service intake，按患者和服务核对 Qualifications 与 Service tasks，并查看 Actual arrivals 列表，与负责人事前记录对照。 | 能唯一定位对应合成患者与服务的目标资格及任务；与事前已核目标店当天无到店记录相比，发起预约后不应新增目标实际到店记录。找不到或无法唯一匹配即停止。 |

## 异常与权限负例

容量不足、时间无效、源店目标相同或无权时不应创建新目标资格。只用负责人另行分配的合成负例；状态未知停止，不为负例重发。

## 一次性提交及停止条件

第4步持久创建目标预约资格及任务并占用目标容量；结果不明由负责人核实，不重复点击、刷新重发或重新登记。不能使用旧患者或历史任务。出现权限、数据异常立即停止。

## 结束条件及后续衔接

唯一资格和任务已可读后本例结束。后续实际到店时由目标前台依法记录到店并对该现有任务报到；先由负责人确认源店旧执行段已合法结束或交还且患者位置释放。仅引用原 RUN；不要重新创建资格。
