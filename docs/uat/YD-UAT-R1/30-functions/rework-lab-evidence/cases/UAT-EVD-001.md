# UAT-EVD-001｜专项技术证据审阅

- 所属阶段：U07；参与岗位：用户审阅者、提供证据的环境负责人或 Codex；层级 L4。
- 真实权限：只读文档访问；私有原始证据须由有权负责人提供脱敏摘要。无需用户数据库、主机或管理权限。
- 对应需求与技术阶段：R01、R25、R26；S00、S13，专项范围按证据另列。
- 当前可验收准备状态：DATA_NOT_READY；各专项证据是否覆盖本次候选及环境均待核，用户结果 NOT_RUN。

## 业务作用与核心行为

识别系统并发、原件保护和恢复能力有何真实证据、证据针对哪一个版本和环境，以及哪些仍未测。用户只审阅材料，不执行技术测试。

## 页面与前置条件

打开本用例和下表固定历史报告；环境负责人提供本次候选及环境标识和有权查看的证据索引。历史报告只证明其中注明的对象、版本和实测层级，不能自动代表当前候选。未提供的证据标 DATA_NOT_READY 或 UNKNOWN；不能为了本例启动服务、执行数据库命令或恢复备份。

## 有序操作和预期结果

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 向负责人取得本次产品版本、环境标识与证据索引。 | 可区分报告日期、版本、环境和测试层级；缺少时注明 UNKNOWN。 |
| 2 | 依次打开表中已链接的历史报告，查阅其限制和来源。 | 能辨认各项限定范围、PARTIAL 与未测内容。 |
| 3 | 对六个专项分别记下提供的证据路径、适用版本及缺口。 | 没有证据的项目保持未验，不凭其他专项推断通过。 |
| 4 | 对需要补充的事实登记问题或环境限制，填写本次 RUN。 | 每项可追溯原始报告或问题 ID；不含真实患者、账号或秘密。 |

## 异常与权限负例

报告无法访问、引用与目标版本不符、缺少原件或批准查看权限时标 BLOCKED／UNKNOWN 并记录原因，不扩大账号权限。

## 一次性提交及停止条件

本例仅阅读和登记，不执行任何业务、备份、升级或回滚。缺少证据不得要求用户重放历史测试；涉及敏感原件时停止并请负责人提供获准脱敏材料。

## 结束条件及后续衔接

六项均已记录证据或缺口后结束；技术补验须由负责团队另行按实际授权组织。用户 UI 满意度可填不适用，历史技术结果不代用户验收 PASS。
