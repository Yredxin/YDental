# UAT-INT-004｜现场登记并分别记录到店与报到

- 所属阶段：U02；验收层级：L2/L3。
- 参与岗位：前台，后续队列工位人员。
- 真实权限：当前门店 frontdesk write 和有效员工／门店范围；所选服务映射、当日营业日与合法可售供给必须有效。demo供给不可售；隔离测试目标须实际匹配真实库、集群、门店并具测试批准。
- 需求／技术阶段及TC：R09、R10、R11、R15；S05-T02/03/04/05/06/12、S06-T03/04。
- 准备状态：DATA_NOT_READY；SOURCE 已核入口，未准备合法测试供给时 BLOCKED，不要求用户修改数据库或供给政策。

## 业务作用与核心行为

以独立合成患者验证现场登记取得资格、记录实际到店与该任务报到是三个动作；不与预约或转诊合用同一来源。

## 页面与前置条件

YDental → Service intake `/ydental/intake`。负责人准备本例专用无进行中接诊的新合成患者、可唯一辨认的服务及区域映射、当日可售时段和营业日；提供时段 UTC 起止，不使用历史来源。若供给未准备、时段过期或患者已有活跃位置，停止交负责人处理。

## 操作步骤和预期结果

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 核对页面门店，在 New qualification 选择 Walk-in registration only、合成患者、服务与区域及负责人提供的 UTC 起止。 | 仅选择本例合成患者与唯一映射；条件不能核实时停止。 |
| 2 | 点击 Acquire qualification 一次。 | Qualifications 列表显示对应患者及服务的有效资格，Service tasks 显示相应待处理任务；此时不是已报到队列位置。 |
| 3 | 在 Record actual arrival 选择同一患者，点击 Confirm actual arrival 一次。 | Actual arrivals 出现本次患者的到店记录；不因此重复建立资格。 |
| 4 | 在 Service tasks 按患者号码和服务唯一定位步骤2任务，点击 Report this task 一次。 | 任务变为 Accepted，Accepted positions 出现对应患者与服务；未唯一定位即停止。 |
| 5 | 将已有任务交给有权限的队列人员，按 UAT-QUE-001 接续。 | 工位人员只处理此已有任务，不再次现场登记、记录到店或报到。 |

## 异常、一次性提交及停止

步骤2、3、4各为持久动作；响应未知先由负责人只读核状态，不重做。不要选择 Walk-in registration and reporting 并再执行步骤3、4：该组合动作同时取得资格、到店和报到。容量不足、日期不符、冲突或权限拒绝时记录并停止，不造备用权限或重复点击。

## 结束条件及后续

合成任务已接受并有可见位置后，引用 UAT-QUE-001；未达到则标 BLOCKED 或 FAIL 并记录证据。
