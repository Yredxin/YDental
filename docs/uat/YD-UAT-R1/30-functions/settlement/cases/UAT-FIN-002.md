# UAT-FIN-002｜模拟线下收款并核销

- 所属阶段：U05
- 参与岗位：收费员
- 真实权限要求：当前门店 settlement write，账号有该门店公司范围。
- 对应需求／技术阶段及 TC：R21；S10-T05–07、T09/10，S12-T11
- 验收层级：L3
- 当前可验收准备状态：ENVIRONMENT_NOT_READY；以下依据源码拟定，须先有独立测试环境和数据，尚未用户验收。

## 业务作用与核心行为

模拟线下收款并核销，使合成业务来源、金额和责任可追溯。

## 页面与前置条件

YDental → Offline settlement（线下结算工作台，`/ydental/settlement`）。UAT-FIN-001 的新合成账单已读回且未付；该收费员、业务日和选用方式未日结。环境负责人提供合成收款场景、匹配该店的演示会计策略与线下方式、可辨认的模拟凭据说明及金额。不得连接或操作真实资金、支付通道。

环境负责人须事先核实完整合成会计策略：销售及调整日记账和科目与门店公司匹配，cash、wechat、alipay、card 四种渠道的日记账均配置，且每种渠道均有 manual 入账方式与对应待结算科目；不满足时 BLOCKED，由负责人准备，用户不自行修改政策。

## 有序操作和预期结果

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 进入 Offline settlement，核对当前门店，搜索并选择同一合成患者。 | 已出账未付清列出目标账单号及余额。 |
| 2 | 记录目标账单余额，展开 Record actual collection。 | 所列勾选项含目标账单号及余额。 |
| 3 | 只勾选目标账单；输入与该余额相等的模拟金额，选择环境负责人指定的线下方式。 | 金额不大于所选账单余额，方式与测试约定一致。 |
| 4 | 核对实际发生 UTC，填入模拟凭据说明。 | 时间、方式及说明与合成测试记录一致；不填写真实凭据。 |
| 5 | 点击确认实际收款并原生核销一次。 | 页面提示受理；不能仅凭提示认定已提交。 |
| 6 | 重新选择患者，查看线下付款与退款及已结清本店账单。 | 出现对应金额和方式的 Collection；目标账单余额为零并出现在已结清列表。 |

## 异常与权限负例

超出余额、跨门店或混合不同患者的账单应拒绝；无 settlement write 不应出现收款操作。负例需单独合成数据，不能为验证拒绝重放目标账单。

## 一次性提交及停止条件

收款建立原生付款及核销记录，即使使用合成数据也属持久提交。结果不明先读回付款和余额；未确认前停止，禁止更换页面、凭据或重复提交。 出现数据、资金或严重权限异常停止受影响操作并记录。

## 结束条件及后续衔接

记录合成 Collection 的原生单号，供 UAT-FIN-003；确认不了结果时不进入退款。
