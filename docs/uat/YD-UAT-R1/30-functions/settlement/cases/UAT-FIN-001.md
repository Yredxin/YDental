# UAT-FIN-001｜确认费用并生成账单

- 所属阶段：U05
- 参与岗位：收费员
- 真实权限要求：当前门店 settlement write，账号有该门店公司范围；查看需 settlement read 或更高。
- 对应需求／技术阶段及 TC：R21；S10-T01–04、T06，S12-T11
- 验收层级：L3
- 当前可验收准备状态：ENVIRONMENT_NOT_READY；以下依据源码拟定，须先有独立测试环境和数据，尚未用户验收。

## 业务作用与核心行为

确认费用并生成账单，使合成业务来源、金额和责任可追溯。

## 页面与前置条件

YDental → Offline settlement（线下结算工作台，`/ydental/settlement`）。环境负责人已在独立合成环境配置该店 demo_confirmation 测试会计策略、销售日记账和科目；准备一个新合成患者及其一条已确认、未出账的正数费用，记录患者号、项目和金额。费用来源由治疗用例唯一产生；不重新执行治疗。当前收费员该费用业务日无已锁定日结。

环境负责人须事先核实完整合成会计策略：销售及调整日记账和科目与门店公司匹配，cash、wechat、alipay、card 四种渠道的日记账均配置，且每种渠道均有 manual 入账方式与对应待结算科目；不满足时 BLOCKED，由负责人准备，用户不自行修改政策。

## 有序操作和预期结果

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 进入 Offline settlement，核对页面当前门店。 | 门店与准备的合成门店相同。 |
| 2 | 在 Patient lookup 输入合成患者姓名或编号，点 Search for a patient，再点唯一匹配患者链接。 | 患者被明确选择；搜索列表本身不代表已选中。 |
| 3 | 查看今日或历史已确认费用，展开 Source trace，核对患者号、项目和金额。 | 费用与准备记录相符；待核对费用不选作出账。 |
| 4 | 展开 Select fees to bill，勾选唯一目标费用，折扣金额保留 0。 | 所选患者号、业务日及金额与第3步一致。 |
| 5 | 点击生成原生过账账单一次。 | 页面提示受理；该提示本身不是持久提交证明。 |
| 6 | 重新查找同一患者，在已出账未付清查找账单号、原金额和应收余额。 | 新账单原金额及余额等于该费用金额；记录账单号供收款使用。 |

## 异常与权限负例

无 settlement write 不应出现出账操作；待核对费用不得出账，非本店来源应拒绝。不得主动重复测试既有来源；若偶然出现重复，由负责人核查原请求和唯一账单：全部来源已属于同一账单且无折扣时可能返回原账单，其他组合可能拒绝；结果不明时停止。负例必须使用独立新合成对象；无适用对象时记 BLOCKED。

## 一次性提交及停止条件

出账会创建过账账单和来源关联。提交后不要重复点或另开页面重试；结果不明先按患者和账单记录核实，无法确认则停止。 出现数据、资金或严重权限异常停止受影响操作并记录。

## 结束条件及后续衔接

仅在唯一新账单已可读回后进入 UAT-FIN-002；无法确认账单状态即停止并请环境负责人核实。
