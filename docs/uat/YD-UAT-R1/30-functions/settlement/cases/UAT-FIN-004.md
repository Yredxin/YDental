# UAT-FIN-004｜收费员合成日结

- 所属阶段：U05
- 参与岗位：收费员、必要时财务审批人
- 真实权限要求：当前门店 settlement write 可确认本人的日结；解锁需 finance_approval write，进入页面需 settlement read。各账号须有该门店公司范围。
- 对应需求／技术阶段及 TC：R21；S10-T15/16，S12-T11
- 验收层级：L3
- 当前可验收准备状态：ENVIRONMENT_NOT_READY；以下依据源码拟定，须先有独立测试环境和数据，尚未用户验收。

## 业务作用与核心行为

收费员合成日结，使合成业务来源、金额和责任可追溯。

## 页面与前置条件

YDental → Offline settlement（线下结算工作台，`/ydental/settlement`）。UAT-FIN-002、003 的收退款使用同一执行收费员、同一门店业务日及线下方式，环境负责人已确认这些独立合成金额及 UTC 转门店日期；该收费员该日该方式无已确认日结。日结汇总该店、该收费员、该业务日、该渠道的全部收款与实退，以及该店该收款人的截止确认时尚未终结的退款申请；负责人必须事前核定完整范围和预期金额，不能安全核实时 BLOCKED。若条件不符应单独准备并核算数据，不套用本例数字。

## 有序操作和预期结果

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 以实际执行收退款的收费员进入 Offline settlement，核对当前门店。 | 门店和账号与该收退款的执行记录一致。 |
| 2 | 核对前述已读回的合成收款额、已完成实退额和未终结退款申请额。 | 准备独立期望：收款、实退及待处理额度分别列出，不把待处理当已退款。 |
| 3 | 展开 Complete daily close，输入该门店业务日并选择对应线下方式。 | 日期和方式与准备记录一致，不是未来日期。 |
| 4 | 点击确认日结并锁定一次。 | 页面提示受理；不以提示作为持久提交证明。 |
| 5 | 在收费员日结查找对应日期、收费员和方式。 | 状态已确认；Actual collections、实退和待处理快照分别等于准备值。 |
| 6 | 展开 Source trace 并记录日结标识与周期。 | 可识别该次日结；净额按收款减实退计算，不减待处理快照。 |

## 异常与权限负例

已确认的同收费员、门店、业务日和方式不能再次日结；财务解锁是另一个持久动作，本例不执行。无 settlement write 不应出现确认按钮；若需负例使用另一组新合成数据。

## 一次性提交及停止条件

确认日结会锁定该收费员、业务日及方式的相关操作。结果未知先查日结记录并由负责人核实，禁止重试、解锁或重新开账来补证。 出现数据、资金或严重权限异常停止受影响操作并记录。

## 结束条件及后续衔接

日结记录与预先核算的三个金额一致并已登记；后续只读文书或报表按对应用例进行。
