# UAT-FIN-003｜模拟退款申请、独立审批及退款登记

- 所属阶段：U05
- 参与岗位：收费员、不同账号的财务审批人
- 真实权限要求：申请和退款登记：当前门店 settlement write；审批：finance_approval write 且须为不同于申请人的账号，进入工作台另需 settlement read；均需有该门店公司范围。
- 对应需求／技术阶段及 TC：R21；S10-T08、T11–14，S12-T11
- 验收层级：L3
- 当前可验收准备状态：ENVIRONMENT_NOT_READY；以下依据源码拟定，须先有独立测试环境和数据，尚未用户验收。

## 业务作用与核心行为

模拟退款申请、独立审批及退款登记，使合成业务来源、金额和责任可追溯。

## 页面与前置条件

YDental → Offline settlement（线下结算工作台，`/ydental/settlement`）。UAT-FIN-002 已读回一笔新合成收款；负责人确定可退款额度、测试金额、合成线下模拟退款及说明。申请人和审批人是不同账号；申请和退款发生的业务日/方式均未日结；负责人还须核实该渠道有 manual 出账方式；退款实际发生 UTC 不得早于申请时间。不得操作真实资金或支付通道。

## 有序操作和预期结果

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 收费员在 Offline settlement 搜索并选择合成患者，在 Collection 找到 UAT-FIN-002 收款。 | 收款单号及金额与前例记录一致。 |
| 2 | 展开该笔申请退款，填写不超过该笔收款可退额度的合成金额及原因，点击申请退款一次。 | Refund request 出现对应原收款、金额和申请状态；申请不是实际退款。 |
| 3 | 交由不同账号的财务审批人登录同店并打开该退款记录。 | 目标申请及原收款一致，出现 Review refund request。 |
| 4 | 审批人填写审批原因，点击另一人批准，在途一次。 | 退款状态变为已批准、等待线下实退；此时尚未登记实际退款。 |
| 5 | 收费员重新打开目标记录，展开 Confirm actual refund，核对实际退款 UTC 并填写模拟线下退款凭据。 | 金额与已批准申请一致，模拟说明不含真实财务信息。 |
| 6 | 在模拟线下退款事实已确认后点击确认已实际退款一次。 | 目标退款状态变为已完成；原收款及退款记录均可定位。 |
| 7 | 记录退款状态及金额，交给同一执行收费员做日结。 | 审批与实退分别留有记录；不能以审批状态代替实际退款。 |

## 异常与权限负例

申请人不能批准自己的申请；超过已收款且已占用额度应拒绝。未知或失败状态会占用额度；必须由负责人核查实际未付款及权限后处理，不能假定无退款或盲目恢复。负例只用独立申请，不重复本次退款。

## 一次性提交及停止条件

申请、审批及实退各自持久提交；实际退款登记生成原生退款付款及贷项。每步仅一次，结果未知先核对应记录，禁止重新申请或重复执行。 出现数据、资金或严重权限异常停止受影响操作并记录。

## 结束条件及后续衔接

目标申请已完成并可读回，记下原收款和退款金额，再进入 UAT-FIN-004；否则停止并报告。
