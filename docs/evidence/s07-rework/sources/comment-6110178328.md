# [GPT-DECISION] YD-N1 后续验收流程调整：阶段技术通过后继续，最终统一用户验收

用户在当前对话明确决定：

> **继续开发，最后统一验收。**

因此从当前S02开始，YD-N1后续协作流程调整如下。本评论取代此前“每个阶段GPT技术复核后必须等待用户逐阶段验收才能进入下一阶段”的流程要求；不改变任何业务需求、测试用例或阶段边界。

## 新流程

1. 每个阶段仍保持：
   - 独立Codex会话；
   - 独立阶段Issue；
   - 固定产品/测试/证据提交；
   - Codex自测；
   - GPT独立技术复核；
   - 发现阻断则在原阶段返工，直到技术复核PASS。

2. 当GPT技术复核PASS后：
   - 该阶段自定义“执行状态”进入 **待用户验收**；
   - 阶段Issue **保持OPEN**；
   - 不写“已验收”，不关闭Issue；
   - 用户无需逐阶段再次确认；
   - 可以直接启用下一阶段。

3. 后续S03—S13按顺序继续：
   - 前一阶段技术复核PASS即可作为下一阶段开发前置；
   - 不因前一阶段仍OPEN/待用户验收而阻塞；
   - 不允许跳阶段并行开发，除非用户以后另行明确授权。

4. 最终统一验收：
   - S13技术复核PASS后，由GPT汇总S00—S13已交付范围、NOT_RUN/生产待定、跨阶段集成结果和最终验收清单；
   - 用户进行一次统一效果验收；
   - 用户统一验收通过后，再批量将仍OPEN的阶段Issue自定义执行状态改为“已验收”并关闭；
   - #23总计划最后收口。
   - 已经在旧流程下由用户明确验收并关闭的S00/S01保持原样，不回滚。

5. 生产发布仍是独立授权：
   - “最终统一验收通过”不自动等于生产部署；
   - 生产参数、生产迁移、正式账号/角色、备份恢复等仍按所属阶段和最终发布授权处理。
