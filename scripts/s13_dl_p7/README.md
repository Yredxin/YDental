# DL-P7 runtime binding

Stage-only specialization of the reviewed DL-P6/S12/S11 tools. The existing
synthetic target, filestore, process-birth checks, read-only identity/grant probe,
independent exact-artifact admission, scope expiry and normal shutdown remain.
Earlier stage owner records, including DL-P6, prevent a new window.

Only `ydental_inventory` is an allowed module for the protected one-shot loader.
The projection retains all current business and original-file coverage; the
module list is not a limit on protected business tables. Old stage scripts,
runtime records, admissions and STOP history are never rewritten.

Use the existing project virtual environment (`../.venv/bin/python`), not an
unrelated system interpreter. `test_runtime.py` is a pure boundary check: it
neither connects to PostgreSQL nor starts Odoo. A successful test is not runtime
admission or product acceptance.

The private provider, current scope, probe, complete checkpoint and independent
review must be bound using the normal `runtime_config.py`, `admission_probe.py`
and `bind_admission.py` flow before `launcher.py start`. Browser and HTTP clients
retain the exact owned-run/candidate check. Credentials and sessions are never
stored in evidence or public documents.

All raw evidence stays in ignored `.local/dl-p7/`. Only the required user plan,
public code and sanitized reports are committed. No stock action, scan POST,
PDF or original generation is part of this stage.

The HTTP adapter refuses business POST before dispatch. The only non-read
requests supported in this stage are normal login, session identity and original
store selection. Presentation submission contracts belong in an in-memory
component, with no submit dispatch or network; this restriction does not alter
the live product's legitimate abilities.

For a committed current P7 candidate, the main operator creates fresh resource
metadata with `runtime_config.py create --candidate <HEAD> --operator /root
--hours 8`, then collects a new `admission_probe.py --provider <absolute-private-
runtime> --output <absolute-new-private-probe> --operator /root` and complete
`protected_snapshot.py collect --phase baseline --label <label> --candidate
<HEAD> --modules ydental_inventory`. Neither a pure test nor these observations
constitutes admission. A real non-implementer reviews the exact runtime, probe,
checkpoint and launcher hashes before `bind_admission.py --probe <probe>
--checkpoint <checkpoint> --review <review>`. Use `launcher.py --help` for the
existing supervised start/status/stop interface; never modify an expired prior
stage scope or replay a module upgrade merely to collect images.

P7's executed browser evidence uses the exact per-run sources and dependency
snapshots indexed in `docs/reports/s13-dl-p7/evidence-index.md`. The broad matrix
client is the frozen preparation driver, not a reason to replay its old failed
WebKit focus assumptions or JS-off asynchronous waits. Private finite clients
separate natural Tab traces, keyboard-modality focus states, native JS-off
viewport capture and component fault checks. Their original commands, sources,
actual exit codes and failed attempts remain in the stage evidence. None of
these tools changes a live form's submission capabilities.
